本清单用于稳定版本候选的最后一次集中检查。构建、安装验证和恢复演练均使用
系统临时目录，不在仓库内生成 `dist/`、测试数据库、导出或日志。

## 发布前整理

- [x] `pyproject.toml` 与 `social_database.__version__` 使用同一个稳定版本号。
- [x] `CHANGELOG.md` 记录版本日期、主要变化、兼容性与明确排除项。
- [x] README、安装、运维、架构、性能和路线图与实现一致。
- [x] 运行与开发依赖完整，`python -m pip check` 无冲突。
- [x] 私有输入、数据库、备份、输出、虚拟环境和构建产物均不在 Git 范围内。
- [x] 实际数据库已完成一致性备份、候选副本检查和临时文件清理。

## 集中验证

- [x] `python -m pytest` 全部通过，测试只使用 pytest 临时目录。
- [x] `python -m build --outdir <系统临时目录>` 同时生成 wheel 与 sdist。
- [x] wheel 和 sdist 的版本、核心文件、许可证与元数据正确。
- [x] wheel 安装到独立临时目标后，可以从仓库外导入并运行 CLI。
- [x] 实际数据库 `check` 返回健康，schema、关系观察和 FTS5 内容一致。
- [x] 实际数据库在最终检查前后 SHA-256 不变。
- [x] HTTP 认证、JSON 幂等、冲突和请求边界通过测试。
- [x] Compose 配置、Docker 构建、容器 CLI、健康探针和受认证 API 通过验证。
- [x] `git diff --check` 通过，`git status --short` 只包含预期发布变更。
- [x] 所有发布临时目录已经删除。

## 提交、标签与推送

1. 创建单一发布准备提交，并确认工作区干净。
2. 用户确认后创建带说明的 `vX.Y.Z` 标签。
3. 推送分支/提交和标签，确认远端 CI 全部通过。
4. 若托管平台需要 Release，再由该标签生成发布说明；不要提交本地构建产物。

标签和推送是外部状态变更，不包含在默认的本地发布检查中。
