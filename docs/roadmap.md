# 项目范围与路线图

## 项目定位

SocialDatabase 是群成员历史数据的聚合、保存和检索工具。当前版本消费外部
产生的 xlsx 或标准 JSON 批次，不负责自动获取群成员数据。

导入采用非破坏性合并：

- 新记录写入数据库。
- 新非空值更新最后已知资料。
- 空值不清除旧值。
- 新数据源缺少某个成员时不删除历史关系。

## 当前阶段

当前核心能力包括：

- 多工作表 xlsx 校验与导入。
- 标准 JSON v1 批次导入，以及与 xlsx 共用的格式无关合并核心。
- 完整保存现有来源的 19 个字段和采集来源元数据。
- SQLite 规范化模型和事务 upsert。
- 数据源哈希、重复跳过和强制重处理。
- 导入批次、来源统计和关系观察记录。
- 按字段、多用户分页搜索，数据库统计和批次查询。
- FTS5/LIKE 混合搜索、事务内索引同步、健康检查与人工重建。
- JSON、CSV 和 xlsx 搜索结果导出。
- 数据库健康检查、一致性备份和恢复操作说明。
- 受认证 HTTP 搜索、统计、批次导入和健康检查 API。
- 非 root Docker 镜像、Compose 持久卷和容器健康检查。
- Python 3.10、3.12、3.14 持续集成。

## 0.5.0 稳定版本

已完成：

- 建立 83,580 条关系的只读搜索性能基线，且未输出成员明细。
- 确认 nickname 与 any 查询超过交互目标，决定验证 FTS5 trigram 加速。
- 完成可重建、可清理的临时 FTS5 原型；实际库全部可用场景与 `LIKE`
  命中用户集合一致，昵称和任意字段查询获得显著加速。
- 确认短于 3 个字符以及不具收益的群 ID 查询应保留 `LIKE` 回退，正式
  接入采用混合路由。
- 完成 schema 2、导入事务内全量同步、自动 LIKE 回退、内容一致性检查和
  `reindex` 恢复命令。
- 完成实际数据库 schema 1→2 迁移与完整分页复测，全部场景达到交互目标。
- 完成一致性备份、恢复候选健康检查与清理演练。
- 补齐稳定版本号、变更记录、分发包构建和发布检查清单。

## 0.6.0 数据完整性与适配

- schema 3 补齐 sex、age、area、level、qq_level、title_expire_time、
  unfriendly、card_changeable、is_robot、shut_up_timestamp 和 role。
- 扩展字段缺失时保持旧版 xlsx 兼容，存在时参与非破坏合并与导出。
- 建立带格式版本、生产方和采集时间的 JSON v1 契约；AstrBot 可作为外部
  生产方输出该格式，核心包不依赖 AstrBot。
- 搜索和导出公开关系首次/最近观察批次及时间，但仍不从缺席推断退群。
- 数据库初始化先拒绝未来 schema，避免检查报错前产生任何建表修改。

本版本不加入采集器、HTTP 或 Docker，以便先稳定未来服务和插件共同使用的
数据边界。

## 0.7.0 服务化基础

- schema 4 为 JSON v1 增加可选稳定 `batch_id`，插件重试不依赖原始文件字节。
- HTTP API 提供搜索、统计、导入历史、JSON 导入和完整健康检查。
- Bearer 令牌保护全部成员数据接口；存活与就绪探针不返回成员或路径信息。
- 服务采用单 worker、串行写入、SQLite WAL 和可配置请求边界。
- Docker/Compose 使用非 root 用户、持久卷、只读容器文件系统和健康检查。

## 0.8.0 集成与生产运维

- 实现或独立维护 AstrBot 上传插件，加入本地待发送队列、稳定批次 ID、重试和
  超时策略。
- 在云服务器反向代理层配置 HTTPS、来源限制和令牌轮换。
- 完成长时间运行、并发读取、导入中断、容器升级和实际恢复替换演练。
- 根据真实运行负载决定是否需要任务队列；当前仍保持同步单写入模型。

在数据源能够明确提供成员状态或完整快照范围后，再考虑增加在群/退群状态
和事件记录。单纯未出现在某次批次中仍不得改变状态或删除历史关系。

## 远期数据获取

自动获取数据不属于当前核心范围。远期可以：

- 自建采集器并输出标准批次。
- 继续使用 AstrBot 插件生成 xlsx。
- 让 AstrBot 插件向未来 HTTP 服务提交现有标准 JSON v1 或其兼容后继版本。

采集器应作为外部适配器，核心合并和数据库逻辑不依赖 AstrBot。手动 xlsx
导入始终保留为独立后备方式。
